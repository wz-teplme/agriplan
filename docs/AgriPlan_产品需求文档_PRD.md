## 1. 背景与问题

农业技术服务公司（典型如中化 MAP 模式）的核心业务链是：**SR（技术经理）为客户制定种植方案 → 技术确认 → FR（一线农艺师）交付与巡田 → 季末复盘 → 下一年参考**。

当前普遍靠「人工经验 + Excel」运转，存在四个痛点：

1. **方案依赖个人经验**：同一地块多年的方案散落在人脑里，人员变动即断档。
2. **数据不可追溯**：用量、价格、依据来源没有版本记录，出问题说不清。
3. **重复劳动多**：查历史、起草、核算、复核占用大量人工时间。
4. **跨季不留存**：今年确认的方案，明年无法直接作为参考。

## 2. 项目目标

- 把「客户 / 地块 / 种植季 → 方案研制 → 草稿确认 → 物资核算 → 现场记录 → 跨季留存」整条业务链落成一套可运行、可追溯的系统。
- 用**可控**的方式引入 LLM/Agent 辅助方案研制与解释，但**模型不能替代人工的专业确认、权限与授权**。
- 先跑通「业务正确 + 工程可靠」，再逐步接入真实模型、真实 RAG 与外部系统。

## 3. 目标用户与角色

| 角色 | 职责 | 有权确认什么 |
| --- | --- | --- |
| AR 业务经理 | 接洽、报价、AR→SR 交接、行情授权 | 商务资料与职责内操作 |
| SR 技术经理 | 多客户沟通、测土调查、方案研制、技术确认、巡田、复盘 | 专业事实、技术方案 |
| FR 一线农艺师 | 交付、阶段安排、巡田、作业实际、异常提报 | 现场实际 |
| 合作客户 | 授权行情、售粮报告、信息补充 | 自身情况与售粮决策 |
| 专业负责人 | 资料、参数、规则、模板、案例审核发布 | 公司级专业依据 |

> 一个 SR 可负责多位客户；SR/FR 共用田间服务；**不按 AR/SR/FR 各建一个 Agent**。

## 4. 产品范围与边界

### 4.1 系统边界

- 独立响应式网页应用：内部工作台适配电脑，现场/客户页面适配手机，不安装 App。
- CRM / ERP / OA / 财务作为**外部系统**，通过授权接口集成，AgriPlan 不承载它们的核心职责。
- 模型可研究、解释、提出候选；**不能**批准采购、修改合同、启用执行版、代客户交易。

### 4.2 明确不做

- 不自动交易、不远程农机控制、不自动学习专业规则、不按角色各建 Agent。

## 5. 功能需求

### 5.1 身份与权限（P0）

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| SR/FR 登录与会话 | ✅ | scrypt 密码哈希、服务端会话、角色限制 |
| 客户责任隔离 | ✅ | SR 只看自己负责的客户，FR 只读职责内对象 |
| 同源写入 / CSP / 输出转义 | ✅ | 写请求同源校验、CSP、请求体大小限制 |
| 客户市场账号 / 邀请 / 激活 / 撤销 | ⬜ | AR 限额邀请、一次性激活、到期撤销（阶段 4） |

### 5.2 客户与地块（P0）

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| 新建客户 / 地块 / 种植季 | ✅ | 同地块可新建下一季 |
| 多地块、客户主档编辑、人员转交 | 🟡 | 现仅单地块；多地块与转交规划中 |
| CRM 关联与同步 | ⬜ | 阶段 5 |

### 5.3 主方案研制（P0，核心价值）

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| 同地块历史优先 + 近似方案补充 | ✅ | 演示范围：历史摘要 + 脱敏案例 |
| 持久研究作业（Worker + 幂等 + 恢复 + 取消） | ✅ | 创建返回 202、租约令牌、重启重领 |
| 确定性核算（面积 × 用量 × 目录单价） | ✅ | Decimal，来源/公式/取整可追溯 |
| 草稿编辑 + 技术确认（版本控制） | ✅ | revision + 乐观并发，正式版不可原地覆盖 |
| 补问 / 恢复 | ✅ | 单类补问（用量缺失），回答后恢复 |
| 真实模型驱动的结构化研制 | ⬜ | 模型接口已设计并用 Mock 验证，未接真实 key（阶段 2F） |
| 语义 RAG / 专业资料库 | ⬜ | 现为 4 篇演示资料的关键词检索（阶段 2+） |

## 8. 风险与依赖

- **真实模型**：需配置支持 JSON 模式的模型 API key；模型语义质量尚未验证。
- **专业资料**：真实农艺资料、审核参数需专业负责人提供。
- **外部系统**：CRM / ERP / OA / 财务的品牌与接口待确认。
- **专业正确性**：系统核验结构/版本/数字，不保证农艺语义正确，最终由 SR 确认。
