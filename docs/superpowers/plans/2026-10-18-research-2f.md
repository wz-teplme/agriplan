# Research 2F Local Evaluation Implementation Plan

> **For agentic workers:** Use executing-plans; independent metrics, runner and report work may run with separate subagents under dispatching-parallel-agents. No Git repository; edit the existing local project.

**Goal:** 可运行的隔离案例评测、调用证据及绑定人工复核，不冒充真实/专业验证。

**Architecture:** model_metrics.py观察原HTTP通道；evaluation.py复用Store/services/Worker隔离执行；eval_report.py输出JSON/HTML和人工模板；evaluate.py提供CLI。

**Tech Stack:** 已有Python、SQLite、httpx、Pydantic、stdlib，无新依赖。

**Spec:** docs/superpowers/specs/2026-10-18-research-2f-design.md。

## Global Constraints

- 本轮不进行外部模型调用，不填造农艺评分，也不把2F或第二阶段整体标为已验收。
- 每例单独临时库，不接受生产库路径，不读取当前客户数据；不自动确认P。
- 未来live必须显式--allow-network、--max-calls和--max-model-seconds，配置完整才允许。
- 供应商缺少token用量时保留null，不填零；费用未配置单价时null，不编造金额。
- 不保存密钥、地址查询参数、请求正文、供应商错误正文；HTML文本全部转义；报告不覆盖旧文件。

### Task 2 隔离案例与CLI

Interface:

- [ ] 测试先红：8例预期结果，零依据limited仍可自动检查通过，缺用量不编造C；当前业务库不变；live无授权/预算/配置拒绝且不发送请求。
- [ ] 实现固定案例、每例临时Store及原services/Worker；记录全部检查及安全异常类别，遇到失败仍输出失败身份。
