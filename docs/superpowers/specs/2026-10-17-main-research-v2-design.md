# 阶段 1：资料、结构化草稿与质量门槛设计

日期：2026-10-17。状态：用户已确认，按六阶段路线从本阶段开始实现。

## 目标

让现有主研制流程具备可审阅的结构化结果、可追溯依据和真实的确认门槛，先解决“无证据仍能确认”以及“不同问题得到相同解释”。为阶段 2 的真实模型研制建立可校验输入输出。

本阶段完成后仍不宣称整套专业 Agent 已完成：真实资料充分性、真实模型研制质量、动态多任务和独立市场研究在后续阶段分别验收。

## 范围

1. 文本/Markdown 专业或流程资料的保存、版本、范围、用途、审核发布与撤回。
2. 每条主要建议的结构化措施、历史关系、依据引用、条件、限制及待决项。
3. 基于固定候选版本的五维评价、具体问题与技术确认门槛。
4. 对历史差异、用量来源、金额、限制和商务状态分别读取相关数据作答；无依据的问题明确说明未知。问题不改事实或方案。
5. 草稿编辑重新评价，资料撤回或版本变化后旧评价不可直接通过确认。
6. 工作台可查看资料与依据、评价及阻塞项；支持原有演示库增量迁移。

本阶段不做 OCR、语义向量库、自动施肥处方优化、真实市场来源或商务放行。资料的文本格式先支持 UTF-8；文件型报告在阶段 2 保存原件并扩展提取。

## 数据设计

保留现有 customers、seasons、runs、jobs、candidate_versions、plans、records 和 audit。新增模块内的关系与结构，不复制整个业务平台。

- **资料版本**：文档 ID、版本 ID、标题、正文、内容哈希、类型（流程/专业）、用途、作物/地区、适用条件、来源、定位、有效时间、范围（共享/指定客户）、状态（draft/published/revoked）、演示标识、创建/发布/撤回人和时间。
- **资料片段**：版本 ID、段落定位、文本和适用元数据；小语料采用结构化过滤加词法检索，保留后续语义检索扩展点。
- **候选内容 v2**：summary、constraints、measures、materials、stages、history_decisions、evidence_refs、calculation_refs、limitations、pending_decisions。
- **measure**：类型、建议正文、成立条件、确认事实引用、资料版本/片段引用、历史引用、计算引用，以及是否涉及专业判断。
- **评价快照**：run ID、C 版本、输入 R、内容哈希、资料与产品版本、评价规则版本、五维结果、issues、状态和创建时间。
- **issue**：类型、severity、关联建议/字段、依据、说明、责任、关闭条件。补录文字不能自动关闭问题，重新评价决定关闭。

沿用现有 knowledge 的演示内容，不把它们自动升级成可支持任意专业处方的资料。增量迁移显式记录数据库版本，旧 C/P 内容可读并标为旧规则；旧 P 保留，不能偷偷补上新评价。旧草稿再次确认必须通过新规则复核。

## 资料使用与审核

阶段 1 使用 SR 角色对职责内资料确认发布，并保留发布者记录；阶段 4/5 引入专业负责人后按其管理权限迁移。SR 不因发布资料而取得其他客户范围。

共享资料与指定客户资料分开，检索在数据库查询时过滤。非 published、已撤回、失效或作物/地区不适用的版本不能进入当前可用证据包。历史引用仍可显示当时依据，但明确标失效。

发布操作要求来源、用途、适用范围和确认说明。系统只验证字段及权限，不把“点击发布”当作外部权威证明；演示资料始终带演示身份。

## 候选生成与数值

重用现有核算工具和已确认输入。先把资料、当前条件和历史差异形成结构化研究结果：每一条沿用/调整/不采用都关联原历史与本季条件。

演示模式根据已确认字段及可用资料生成不同的受限内容，界面显示规则演示；缺少专业依据时只生成流程性草稿及具体缺口，不编造专业措施。专业施用数值只能来自 SR 当前确认值或已审核参数，不从预算倒推。

阶段 2 接入模型生成时使用同一候选契约；数值和引用仍经服务器校验。不能用模型返回的“已支持”替代校验或专业复核。

## 评价与确认门槛

五维采用符合、部分符合、不符合、无法评价：条件适配、依据充分、数值一致、完整可执行、风险与调整准备。

程序检查：引用是否存在/可用/获准、输入和产品版本、单位/数字、确认参数、预算、目标硬约束、必需字段、未解决条件。主张支持性按建议类别与资料用途检查；无法可靠判断时创建 needs_review 问题，不能自动判为符合。专业适用性需要明确专业复核，不由相似度或生成文字自证。

有阻塞问题的任务保存草稿并进入 limited，保留具体问题；信息待人确认进入 waiting_input；系统错误进入 failed。证据为空不能被解释为“依据已齐备”。技术确认时重新读取候选内容、当前输入、资料发布/撤回状态和评价绑定版本；旧评价、阻塞问题或失效依据返回 409。

明确区分普通未知项与依赖它的关键判断：非必填土壤数据缺失不会阻止所有起草；依赖该数据的专业主张不能通过确认。技术确认仍不等于商务批准或执行放行。

## 对话与修改

第一批解释能力使用明确的问题类别和当前对象数据：历史沿用/调整、用量依据、金额与预算、资料缺项/风险、版本与确认状态、未接入的合同商务。对未覆盖问题返回范围限制与相关资料，避免所有问题复用同一段固定回答。

每次回答保留问题、类别、所用 R/C/P、资料/计算引用、回答模式和时间。不修改候选或事实。用户明确修改仍通过现有编辑入口提交，保存新 C 与理由，再评价。

阶段 2 才扩展语义模型问答、明确调整意图、结构化修改建议与用户确认；阶段 1 不以简单关键词规则宣称通用智能对话。

## 页面与接口

- 现有方案详情“方案与依据”：显示结构化措施、历史采用理由、金额及引用，兼容旧草稿展示。
- “对话与待确认”：显示具体缺口、问题类别与回答依据。
- “确认与变更记录”：显示当前 C 的五维评价、阻塞项和评价版本；明确不可确认的原因。
- 资料管理复用“知识问答”入口的管理区，添加资料列表/内容、发布/撤回操作及范围标识，不增加不相关统计大屏。
- API 新增资料创建/版本/发布/撤回、候选评价查询/重评；现有研究、编辑和确认 API 执行新门槛。

## 错误、权限与兼容

不匹配 revision 返回 409；无对象范围返回 404；角色无权返回 403；格式/引用错误返回 422。模型/网络不在本阶段关键新增路径，既有可选模型动作调用保持有边界。

新迁移使用事务，保留原业务记录；API 与 Worker 使用同一 schema 版本。写操作记录审计，所有资料正文渲染转义。发布与撤回必须使用同源、对象和角色检查。复制旧资料产生新的明确版本，不覆盖当时引用。

## 必须通过的验收场景

1. 资料为空时保留草稿及缺口，不能完成为“依据充分”或通过技术确认。
2. 草稿引用不存在、未发布、撤回、过期或越权资料时产生具体阻塞问题。
3. 可用流程资料只能支持流程建议，不能被用于证明未审核的农艺处方。
4. 已确认专业参数有来源，数量和金额由现有工具核算，输出引用一致。
5. 同地块预算/面积/品种等条件变化出现在历史采用/调整说明中；无效果资料不声称已验证。
6. 五维评价固定 C/R/依据版本；编辑后必须生成新评价，旧评价不能批准新内容。
7. 草稿生成后依据撤回，再确认会被拒绝；查看历史仍能追溯原版本及撤回身份。
8. 问金额、问历史、问合同得到对应类别和不同依据；未知合同不编造；询问不改变 C/P。
9. 非必填缺项可起草；依赖缺项的判断受限，不能通过删风险项绕过门槛。
10. SR/FR 对象权限、重复回答、旧租约、取消和前端跨对象回归继续通过。
11. 原 v1 演示数据库升级后原有客户、问题、C/P 和现场记录仍可读取，重复启动不重复迁移。
12. 桌面/手机可操作、评价问题可见、确认按钮状态与后端判定一致。

完成后更新阶段进度及实际验证记录。外部专业资料不足或真实模型未测的状态保持未验证，不以本阶段验收替代。
