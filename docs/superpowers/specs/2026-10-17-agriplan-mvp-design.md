# AgriPlan MVP 设计与验收

用户已于 2026-10-17 确认推荐范围：本地运行、主方案业务闭环优先、市场演示分支、预留真实模型配置。

## 目标与边界

从两份修订手册提炼可演示闭环：SR 多客户待办 → 本季资料 → 同地块历史优先 → 证据与工具核算 → 补问/恢复 → 可编辑草稿 → SR 技术确认 → SR/FR 共用现场记录。

响应式网页包含我的待办、客户与地块、方案研制、田间服务、知识问答五入口。方案详情持续显示客户、地块、种植季和版本，提供本季资料、历史参考、方案与依据、对话与待确认、确认与变更记录。

## 技术选择

Python 3.11+、FastAPI/Pydantic、SQLite、原生 HTML/CSS/JavaScript。API 和 Worker 可独立启动；便捷启动器同时启动两者。SQLite 持久保存数据、任务、动作、快照及问题。短事务领取任务，模型调用在事务外执行，租约令牌及输入版本防止过期结果覆盖。首版单 Worker，保留重启恢复能力。

默认规则演示模式可离线运行。配置服务端模型地址、模型名及密钥后，模型在受控动作白名单内选择研究动作，服务端校验并执行。模型不修改权限、专业确认或执行放行。规则模式、演示资料和演示行情明确标注。首版以显式持久状态机代替 LangGraph，关键词检索代替向量检索；不声称已实现 LangGraph/pgvector。

## 数据与权限

演示账号通过密码登录，服务端保存会话和对象责任关系。SR 可管理自己负责的客户与季节；FR 可查看获分配对象并保存现场记录，不能确认方案。另一个 SR 的资料、研究、历史和记录不可访问。

本季资料保存 revision、来源与确认身份；缺失值保留未知。研究保存输入快照 R，草稿保存候选版本 C，技术确认生成不可覆盖的 P 版本。最新技术确认不等于商务批准或允许执行。

同地块历史依据地块 ID 关联，跨客户只能检索显式发布的脱敏案例。没有历史仍可起草；缺少效果资料必须说明局限。演示产品、经验参数、农艺资料和历史均不作为生产农艺依据。

## 研究与核算

允许动作：查询历史、查询证据、提出专业参数补问、确定性核算、内部市场委派、提交草稿。有限动作预算避免循环。缺少 SR 确认的用量参数时只限制相关核算并持久等待；非必填土壤字段缺失不阻止起草。回答保存与恢复作业登记同事务，重复回答幂等，旧版本回答冲突。

用 Decimal 核算面积×已确认用量×目录单价，保存产品版本、事实版本、规则版本和金额取整方式；不凭预算反推施用量，不把未知费用补零，不输出完整净收益。目录价格为演示版本。市场分支比较同口径报价、运输/扣价及净到手价，过期或缺项报价不推荐；无仓储时不能给储粮策略。

模型模式只决定受控动作与解释，关键数字由服务器渲染；没有配置真实模型时不冒充模型研究。外部 API 出错保留任务并标记失败，不静默切换成模型成功。

## 修改与确认

任务内提问只解释当前对象与快照，不修改事实或方案。明确点击编辑草稿并提交才产生新 C 版本及差异记录，金额重算。专业确认要求当前事实版本匹配、无关键待答项及未超预算；确认生成固定 P 版本。正式版修改通过新研究/新草稿重新确认，旧 P 保留。现场记录是实际观察，可不绑定预排任务；不创建虚假的已放行执行任务。

## 验收

1. 新地块可建档，两个客户切换不会混用研究和历史。
2. 同地块多年案例先于共享案例，差异及缺效果说明可见。
3. 缺非必填资料可起草；缺用量确认会等待，回答后可恢复。
4. 2 亩×3 kg/亩×1.25 元/kg = 7.50 元；NaN、负数、无效单位拒绝。
5. 重复启动/回答不增加有效副作用；相同幂等键不同内容返回冲突。
6. 修改资料后旧研究不能通过确认；旧 revision 编辑返回 409。
7. 询问不修改 C/P；草稿修改保留前后版本和人员明确理由。
8. FR 不能技术确认；替换客户、季节、研究 ID 不获得越权数据。
9. Worker 中断后过期租约可重领，旧执行令牌不能提交结果。
10. SR/FR 都能保存巡田实际；记录重启后仍存在。
11. 市场演示清楚标记数据时点，缺费用或过期报价不能参与推荐。
12. 五入口可操作，电脑和手机页面无横向溢出。
