# AgriPlan MVP

根据上级目录两份修订项目手册实现的本地可运行版本。聚焦 **SR 多客户 → 本季资料 → 同地块历史 → 研究/补问/核算 → 可编辑草稿 → SR 技术确认 → SR/FR 田间实际记录**。

当前已完成六阶段路线的第一阶段、第二阶段2A模型候选协议、2B补问与多产品核算、2C讨论与文字修改预览、2D报告原件/pH候选确认，以及2E固定子任务、局部失效和有限恢复。尚未完整实现专业研制、双 Agent、客户市场和全季业务。当前状态见 [实施进度](docs/实施进度.md)，最初核查保留在 [项目文件实现覆盖与未完成清单](docs/项目文件实现覆盖与未完成清单.md)。默认规则生成草稿并解释分类问题；配置模型后可生成结构化候选及语义解释/修改建议，服务器控制数字、引用和保存权限。真实模型语义质量仍未验证。

## 启动

Windows 双击 `start.cmd`，或在此目录执行：

```powershell
.\start.ps1
```

打开 **http://127.0.0.1:8000**。当前电脑的专用 `.venv` 已安装依赖；在新电脑上脚本会尝试创建环境并安装锁定依赖，需要 Python 3.11+ 与包源访问。

报告原件保存在数据库同级的 `source-files/`（默认 `data/source-files/`），SQLite只存元数据、提取历史和来源关联。备份时需同时保存业务数据库及原件目录；只有数据库无法恢复原报告。2D新增锁定依赖pypdf 6.10.0，已有环境升级可执行 `python -m pip install -r requirements.lock.txt`。

手工安装和启动：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -X utf8 run.py
```

指定端口：`start.cmd --port 8010`。Ctrl+C 停止 API 和 Worker。数据保存在 `data/agriplan.db`，重新启动不会重置。

| fr_zhou | FR 周禾；青禾客户，可保存田间实际 | agriplan-demo |

## 五分钟演示

1. 用 `sr_chen` 登录。在“客户与地块”打开 **青禾 / 东河一号田 / 2026**，查看确认用量和 2024、2025 历史差异。可先保存修改后的资料，之后再开始研究。
2. 点击“开始研制”，可勾选市场演示。查看研究动作、默认主建议、产品小计和证据定位。默认示例：300 亩 × 20 kg/亩 × 3.20 元/kg = **19,200.00 元**。
3. 查看草稿质量评价、结构化措施与历史处理理由。在“对话与待确认”询问预算、历史或合同状态，解释不改方案。SR点击“提出修改”，填写手工摘要/阶段及可空理由，先生成修改前后预览；点击“确认保存为新草稿”才生成C2并重新评价。配置模型时也可从自然语言起草修改建议。原“编辑草稿”仍可直接保存明确编辑。
4. SR 技术确认得到 P1。界面分别显示 **技术已确认 / 商务未接入 / 执行未放行**。正式版不能原地覆盖；通过新研究形成新草稿和下一版技术确认。
5. 打开 **丰穗 / 南坡试验田** 发起研制。因缺少确认用量进入等待，填写 **15 kg/亩** 和演示依据，保存后恢复；120 × 15 × 3.20 = **5,760.00 元**。等待期间可处理另一客户。
6. 在田间服务新增巡田、实际作业、异常或季末复盘。切换 `fr_zhou`，可以读取自己负责对象和保存现场记录，但不能技术确认。切换 `sr_liu`，看不到青禾和丰穗资料。
7. 修改本季面积后，旧研究显示输入过期并拒绝确认。在“研究模块与恢复”查看影响，再明确刷新：只重算数量、金额和草稿，保留仍适用的历史、资料和市场结果。旧草稿保留在历史修订中。也可新建研究；草稿可导出 Markdown，包含计算血缘和引用。

“新建客户地块”支持新增当前 SR 负责的对象。第一版不导入真实客户资料、真实农艺规则或真实行情。

本季资料可追加不同公司产品并分别保存确认用量与来源；主、追加产品不能重复，未知用量会形成独立问题。开始研究时可明确要求补齐预算、品种、仓储或pH；默认不强制这些普通事实。多个问题逐项保存并保留其余问题，最后一项回答后自动恢复。例：追加 B 产品5 kg/亩、4.10元/kg，在300亩下为6150.00元，连同主产品19200.00元，合作合计25350.00元；预算门槛使用这个合计。当前目录有两个演示产品，尚无套餐和客户自有物资完整成本模型。

修改预览固定原研究R/C、研究修订和内容哈希。其他窗口已保存、当前事实变化或已技术确认时，旧建议不能套用；同一建议重复保存不会新增草稿。修改只开放摘要/阶段文字，专业用量、产品、品种或预算变化需SR通过本季资料确认并重新研制。FR可询问职责内方案，不能提出或保存技术修改。理由留空标“未记录”，不从聊天推测。

“本季资料”的报告区支持UTF-8 txt/md、文本层PDF、PNG/JPEG原件，单件最多8MiB。上传只保存原件；点击提取后得到未确认pH候选，核对地块、采样日期、原单位和页码/摘录，另点“核对并确认”才写入新R。单位、地块、日期错误或多个/复杂pH标签会阻止确认，可人工转录修正并保留历史。PDF最多30页/100000字/15秒；扫描件或解析失败保留原件转人工，当前没有自动OCR。首版仅映射soil_ph，其他指标保留原文，不生成生产处方。

确认后研究快照保存固定报告来源。仅变更面积等其他字段会继承pH来源，pH数值改变则清除该关联；原件缺失或哈希不符会阻止相关草稿通过质量门槛。迟到报告更新当前R，旧研究显示过期，旧C/P不会被改写。FR可读取职责内报告，不能上传/提取/确认。

研究分为历史、资料、逐行数量、逐行金额、市场演示和候选六模块，保存独立结果引用及输入指纹。面积或用量变化影响数量/金额/候选；适用目录价变化影响金额/候选；仓储变化影响市场/候选。历史复用时重算本季差异，金额复用时重新绑定当前R和计算引用。资料发布/撤回、市场超过七日时效及报告完整性变化会重新检查。旧研究没有模块记录时首次刷新保守重做，不能凭旧检查点伪造复用。正式P需新研究，FR只读。

恢复弹窗绑定研究修订、当前输入和上下文；事务内重新校验职责并登记唯一新作业，旧作业不能回写。每研究最多4代（含初始和最终补问恢复）、每代12动作、每作业3次领取。失败/受限研究可明确有限补查；次数耗尽需新建研究。职责移交后由当前获分配SR恢复，保留原发起身份和恢复审计。

“知识问答”中的资料管理可录入文字或导入 UTF-8 `.txt/.md`（正文最多16000字）。设置来源、定位、范围、用途、类型、有效期、适用条件和审核主张，再填写说明发布。新版本保留原正文；撤回或被新版替代的资料不能用于当前确认。FR 可通过职责内方案查看被引用资料的历史正文及当前撤回身份，不能管理资料。

零依据、引用失效、计算/约束不一致或未解决条件会保留受限草稿并阻止技术确认。非必填 pH 未知仅提示限制。摘要和阶段自由文字仍须 SR 复核；程序核验不代表所有农艺语义或效果已被验证。

同一地块详情还可“新建下一季”：往季已确认的技术 P 版本进入历史参考，新季预算、用量和来源重新确认。现场记录默认不猜测关联版本；明确选择技术版本时，后端核验属于本季且确认时间不晚于实际发生时间。

**演示模式不是 LLM Agent。** 默认用显式的受控状态机验证业务与运行机制；LangGraph、向量数据库和真实外部业务集成没有接入。阶段模板只说明服务流程，不生成生产施肥或用药处方。

SQLite 适合本机和单 Worker 演示。API 和 Worker 分离，短事务领取；模型调用在事务外；执行与提交检查当前职责、输入、token和租约。明确刷新后按六个固定模块复用或重做，本版不实现通用动态依赖图。

## 可选真实模型

复制 `.env.example` 为 `.env`，设置：

```dotenv
AGRIPLAN_MODE=llm
AGRIPLAN_MODEL_BASE_URL=https://api.openai.com/v1
AGRIPLAN_MODEL=你的账号可调用且支持JSON模式的模型名
AGRIPLAN_MODEL_API_KEY=你的密钥
```

地址填到 `/v1`，程序追加 `/chat/completions`。重新启动后新研究使用模型选择受控动作，并在提交阶段请求结构化候选。兼容服务需要支持 `response_format: {"type":"json_object"}`；JSON 模式仅保证 JSON，程序还会用 Pydantic、动作白名单与候选引用目录验证。

动作包括查询历史、查询证据、补问、数量核算、金额核算、限定市场委派、提交/有限重建草稿和停止；历史优先、专业参数、金额与技术确认仍由服务端约束。单次模型请求超时40秒、输入最多128000字符，每代最多12动作、最多4代，作业最多领取3次。JSON/字段/动作或引用协议错误仅有一次修复机会，持续错误标记失败；HTTP错误直接失败。依据不足等适用质量问题最多补查一次并重建一次，反馈包含具体问题及关闭条件。预算超限、专业待决项不会由模型猜测关闭。停止时暂存候选仅供处理，不形成可确认草稿。

候选模型只返回摘要、阶段、审核措施ID、历史处理理由和待决项。确认参数说明、物资数量/金额、约束、引用原文和输入版本由服务器构建；模型不能覆盖关键业务字段。模型待决项会阻止确认，提交时重查当前资料。当前模型目录只开放可用流程主张，不自动生成新的生产处方。摘要和阶段的语义正确性仍须SR复核。

模型讨论使用同一服务端JSON通道，输入限于当前对象事实、草稿、核算、历史、现场记录、实际引用资料、当前评价及同研究最近六轮讨论。返回explain/edit/needs_facts、解释、允许的引用及可选文字建议。询问夹带修改、未知引用或额外业务字段会拒绝；资料不足只提示确认入口，不把聊天当事实。模型调用期间不持有数据库连接，落库前重新检查职责、版本、事实及依据。通用知识入口仍是规则检索。

密钥只在服务端读取。接入外部模型时，研究快照及获准参考会发送到配置服务；先使用合成数据验证。当前未配置真实模型密钥，HTTP协议和工作流使用MockTransport验证；没有进行真实供应商调用或农艺效果评测。

参考：[OpenAI JSON 与结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)、[FastAPI 测试客户端](https://fastapi.tiangolo.com/tutorial/testing/)。

## 测试与独立进程

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
node --check web/app.js
node tests/test_ui.cjs
.\.venv\Scripts\python.exe -m pip check
```

API 和 Worker 分开运行：

```powershell
# 终端 1（读取 .env）
.\.venv\Scripts\python.exe -X utf8 run.py --no-worker
# 终端 2：使用同一环境变量及数据库
.\.venv\Scripts\python.exe -X utf8 -m app.worker
```

独立 `app.worker` 不自动读取 `.env`，需将变量设置在进程环境；便捷启动器自动传给子进程。API 文档在 `/docs`；需要先通过网页登录。任务和回答持久保存，即使浏览器关闭也会由 Worker 推进；异常退出的运行中 job 最多等待 120 秒租约过期后重领。

当前本地验收：124项Python测试、39个前端行为场景通过；完成桌面/手机模块展示、面积R7→R8只重做数量/金额/草稿、仓储R8→R9只重做市场/草稿，旧C1/C2保留，新C3金额仍为25434.50元。数据库增量升级到v6，原两份正式P及报告原件哈希不变。旧问题缺少原始类型上下文时返回明确兼容身份，原始输入版本保持未知。详见[阶段2E验收记录](docs/阶段2E验收记录.md)；报告、讨论预览及多产品证据见前阶段验收记录。
